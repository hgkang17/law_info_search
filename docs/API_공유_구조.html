API와 저장 상태가 어디서 만나고 갈라지는지

화면에 한 줄로 보이는 검색 결과도 목록 조회, 본문 조회, 조문 조회가 서로 다르다. 이 문서는 각 화면이 어떤 법제처 API를 쓰는지와 저장·즐겨찾기·글꼴 중 무엇을 공유하는지 한 기준으로 정리한다.

목록은 한 입구 lawSearch.do에서 target만 바꿔 검색한다.
본문은 목적별 분리 전문은 eflaw, 법령 조문은 eflawjosub를 쓴다.
즐겨찾기는 같은 파일, 다른 상태 법령 전체 별과 조항호목 별은 한 기록에 있지만 독립적으로 판정한다.

법제처 DRF의 URL은 크게 두 개다. 검색 결과를 찾는 단계와 실제 내용을 여는 단계가 분리돼 있고, 두 단계 모두 target이 자료 종류를 결정한다.

중요한 구분

통합검색은 별도 API가 아니라 일반 목록 API와 aiRltLs, aiSearch 결과를 합쳐 보여 주는 화면이다.

화면별 API

같은 법령명이 보여도 결과 행의 출처에 따라 열 때 사용하는 API가 달라진다. 아래 표의 “내용 조회”가 실제 더블클릭 또는 본문 열기 시점의 호출이다.

화면·결과 목록 target 내용 조회 target 현재 동작
통합검색 · 일반 법령 law eflaw 법령 전문을 연다.
통합검색 · AI추천 법령 조문 aiRltLs aiSearch eflawjosub 해당 조문만 연다. 저장 전문 fallback은 사용하지 않는다.
조문검색 · 법령 조문 aiSearch eflawjosub 조문 API로 받은 저장본만 재사용한다.
연관검색 · 법령 조문 aiRltLs eflawjosub 선택한 법령 조문을 추가 조회한다.
일반 행정규칙 admrul admrul 행정규칙 전문을 연다.
AI추천·조문검색 · 행정규칙 조문 aiRltLs aiSearch admrul 예외 전문을 받은 뒤 해당 조문을 추출한다.
자치법규 ordin ordin MST 식별자로 자치법규 전문을 연다.
별표·서식 licbyl admbyl ordinbyl 첨부파일 경로 PDF·HWP 등 원문 파일을 내려받거나 미리 본다.
행정규칙 조문은 별도 취급

현재 법령 조문용 eflawjosub를 행정규칙에 사용할 수 없다. 따라서 행정규칙 조문 결과만 admrul 전문에서 해당 조문을 찾는다.

조항호목 원칙

법령 조문 결과의 단일 기준은 eflawjosub다. 검색목록에 포함된 짧은 본문이나 저장된 법령 전문에서 잘라 만든 내용은 조문검색 결과로 인정하지 않는다.

API 요청

target=eflawjosub, ID=법령ID, JO=조번호로 해당 조 전체를 받는다. 항·호·목 즐겨찾기는 이 조문 API 응답 안에서 필요한 단위만 추출한다.

저장본 재사용 조건

조문검색 화면 스냅샷에는 article_api_source=josub를 기록한다. 이 표식이 없는 구버전 저장본은 무시하고 API에서 다시 받는다.

현재 보장

통합검색 AI추천 법령 조문은 조문 API가 실패해도 저장 전문을 대신 잘라 보여 주지 않는다.

무엇이 공유되는가

“같은 파일을 쓴다”와 “같은 상태로 취급한다”는 다르다. 저장 객체는 공유하되 법령 전체와 조항호목의 판정은 분리하는 것이 현재 원칙이다.

항목 공유 여부 공유 범위와 기준
API 인증키 OC 공유 모든 법제처 API 요청이 같은 인증값을 사용한다.
LawDocumentCache 공유 통합검색, 조문검색, 연관검색, 열람내역, 즐겨찾기, AI 검토가 같은 객체를 사용한다.
최근 검색어 공유 검색 화면들이 같은 RecentSearchManager를 사용한다.
현재 즐겨찾기 프로젝트 공유 어느 화면에서 별을 눌러도 현재 프로젝트 기준으로 판정한다.
법령 전체 별 / 조문 별 상태 분리 같은 법령 JSON을 쓰지만 프로젝트 소속과 별 표시를 별도로 관리한다.
검색목록 캐시 키 분리 같은 폴더를 쓰지만 서비스·검색어·검색범위별 키가 다르다.
조문 참조·3단비교 기능 공유 조문검색 화면이 법령검색 화면의 참조 팝업과 3단비교 기능을 호출한다.
본문 글꼴 설정값 분리 설정 파일과 기본 규칙은 공유하지만 화면별 설정 키는 다르다.

저장 위치와 의미

캐시 루트는 사용자 로컬 앱 데이터의 국가법령정보 통합검색/# law 캐시다. 폴더 이름이 비슷해도 저장 체크가 참조하는 대상은 결과 종류마다 다르다.

하위 폴더 담기는 내용 주의할 점
검색목록 API 검색 결과 목록 서비스·검색어·검색범위별로 구분한다.
저장내역 법령 전문, 상세 화면, 메모, 색상 서식, 즐겨찾기 소속 API로 복원할 수 없는 메모와 즐겨찾기도 있으므로 단순 임시 폴더가 아니다.
조문 eflawjosub 응답 원문 통합검색 AI추천 조문의 저장 체크가 직접 확인하는 대상이다.
별표파일 PDF·HWP 등 첨부 원본 용량 제한을 두고 오래된 파일부터 정리하는 순수 캐시다.
저장 체크의 뜻

일반 법령 행은 전문 저장 여부를, AI추천 법령 조문 행은 그 조항호목 원문 또는 조문 화면 저장 여부를 뜻한다. 즐겨찾기 여부와는 별개다.

즐겨찾기: 같은 기록 안에서 독립

조문 즐겨찾기는 법령 소속과 본문을 잃지 않도록 부모 법령의 저장 JSON 안에 둔다. 물리적 저장 파일은 공유하지만 전체 법령 별과 조문 별을 같은 값으로 계산하지 않는다. 

건축법 저장 기록
├─ favorite_projects                 ← 건축법 전체 즐겨찾기 프로젝트
└─ favorite_articles
   └─ 제1조(목적)
      ├─ jo / hang / ho / mok        ← 조항호목 위치
      └─ favorite_projects           ← 제1조만의 즐겨찾기 프로젝트

건축법 전체만 즐겨찾기

법령 카드만 나타난다. 제1조 별은 켜지지 않는다.

제1조(목적)만 즐겨찾기

조항호목 카드만 나타난다. 건축법 전체 별은 켜지지 않는다.

  • 건축법 전체 별을 해제해도 제1조 별은 유지한다.
  • 제1조 별을 해제해도 건축법 전체 별은 유지한다.
  • 같은 법령 ID라도 대기 중인 별 표시는 조·항·호·목까지 같을 때만 공유한다.

글꼴 설정의 공유 범위

모든 값은 같은 QSettings 파일에 들어가지만 화면마다 키가 다르다. 기본 글꼴과 구버전 마이그레이션 함수만 공통으로 사용한다.

화면 글꼴 설정 키 관계
일반 법령·통합검색 본문 resource_detail_font_family 통합검색 안의 일반 본문과 조문 본문이 함께 사용
조문검색 ai_search_detail_font_family 일반 법령 본문과 값 분리
연관검색 ai_related_detail_font_family 조문검색과 값 분리
판례·법령해석·질의회신 {service}_detail_font_family 서비스별 값 분리
현재 기본값

본문은 굴림 9.5pt다. 과거 휠 동작으로 자동 저장된 Arial은 기본값 버전 5 마이그레이션에서 각 화면이 처음 열릴 때 굴림으로 한 번 복구한다.

코드 기준점

동작을 바꿀 때 먼저 확인해야 하는 파일과 책임이다.

  • molit_cgm_expc_api.py 법제처 URL, 목록·전문·조항호목 API 함수
  • models/law.py 화면 카테고리와 API target 매핑
  • workers/search_worker.py 화면 요청을 실제 API 호출로 연결하는 분기
  • ui/tabs/resource_search.py 통합검색, 조문 캐시, 저장 체크, 즐겨찾기 진입점
  • ui/tabs/ai_search.py 조문검색·연관검색 목록과 조문 API 저장본 검증
  • storage/cache.py 전문·화면 저장과 법령/조문 즐겨찾기 프로젝트 소속
  • storage/paths.py 검색목록·저장내역·조문·별표파일 저장 위치
  • ui/widgets.py 본문 글꼴 기본값 마이그레이션
이 문서는 현재 소스 코드의 동작을 기준으로 작성했다. 법제처 API target이나 저장 구조를 변경할 때는 화면별 호출 경로와 저장 체크·즐겨찾기 판정을 함께 갱신해야 한다.
